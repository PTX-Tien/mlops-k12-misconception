# G11-02 — Staging CD, manual release & rollback

**Epic/Gate:** G11
**Owner (function):** SRE+Platform
**Depends on:** G11-01; G9-03
**Priority:** P1 (learning sequence)
**Status at creation:** BACKLOG (chưa thực hiện/chưa nghiệm thu)

## User story / Why
Kiểm soát chuyển từ model candidate đến staging.

## Input & prerequisite
Các dependency phải PASS, phải có quyền data/server tương ứng, đã đọc `01_PROJECT_CHARTER_SRS.md` và `10_SECURITY_DATA_POLICY.md`. Nếu phần prerequisite thiếu, chuyển trạng thái `BLOCKED` và ghi rõ owner.

## Work breakdown (tự giải, không cung cấp solution)
Build/package pinned version; approval job/manual gate; staging smoke; rollback rehearsal. Thiết kế trước khi code; nêu ít nhất 1 phương án thay thế và rủi ro. Thực hiện theo *small diff*, cập nhật tài liệu và tests tương ứng.

## Deliverables (paths do implementer chọn rồi khai trong PR)
Release checklist + staged deployment evidence. Nộp `docs/enterprise/templates/SUBMISSION.md` với changed paths, chạy test có command/exit, commit SHA và risk statement. Không đẩy data/weights không được phép lên repo.

## Acceptance criteria (verifiable, no fake evidence)
- **AC-G11-02-01:** No direct main→production; release/rollback path tested; human owner identified.
- **AC-G11-02-02:** Có ít nhất một negative/edge case được kiểm thử độc lập: **Staging health fails: block release**.
- **AC-G11-02-03:** `python -m pytest -q`, `python -m ruff check src tests`, `git diff --check` pass nếu có source changes; riêng document-only thay thế bằng link/lint docs khi hợp lý.
- **AC-G11-02-04:** Reviewer có đủ input versions, test logs đã redact, artifact paths và kết luận rõ PASS/FAIL/NEEDS_EVIDENCE.

## Acceptance test design
- Happy path: dùng input hợp lệ ở môi trường được phép, đo output theo AC-01.
- Failure path: Staging health fails: block release.
- Regression: chạy lại các test liên quan đến các ticket đã PASS; tránh sửa code/metric/split mà không cập nhật version.

## Evidence required
- Implementation plan 5–10 dòng + PR diff/commit.
- Test command, exit code và output tóm tắt (đã redact).
- Artifacts có hash/run ID khi liên quan dataset/model.
- Giải thích điều chưa được kiểm chứng và giới hạn của kết quả.

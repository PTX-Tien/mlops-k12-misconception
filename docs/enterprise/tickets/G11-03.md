# G11-03 — Secrets, dependency & artifact security review

**Epic/Gate:** G11
**Owner (function):** Security+QA
**Depends on:** G11-01; G10-02
**Priority:** P1 (learning sequence)
**Status at creation:** BACKLOG (chưa thực hiện/chưa nghiệm thu)

## User story / Why
Phòng leak data khi tạo CI/CD, artifacts, logs.

## Input & prerequisite
Các dependency phải PASS, phải có quyền data/server tương ứng, đã đọc `01_PROJECT_CHARTER_SRS.md` và `10_SECURITY_DATA_POLICY.md`. Nếu phần prerequisite thiếu, chuyển trạng thái `BLOCKED` và ghi rõ owner.

## Work breakdown (tự giải, không cung cấp solution)
Review env variables, secrets, dependency licensing; artifacts retention and private endpoints. Thiết kế trước khi code; nêu ít nhất 1 phương án thay thế và rủi ro. Thực hiện theo *small diff*, cập nhật tài liệu và tests tương ứng.

## Deliverables (paths do implementer chọn rồi khai trong PR)
Security signoff checklist + issues. Nộp `docs/enterprise/templates/SUBMISSION.md` với changed paths, chạy test có command/exit, commit SHA và risk statement. Không đẩy data/weights không được phép lên repo.

## Acceptance criteria (verifiable, no fake evidence)
- **AC-G11-03-01:** No credential or student data in logs/artifacts; failures tracked; threat model updated.
- **AC-G11-03-02:** Có ít nhất một negative/edge case được kiểm thử độc lập: **Malicious dependency or joblib artifact từ bên ngoài: response?**.
- **AC-G11-03-03:** `python -m pytest -q`, `python -m ruff check src tests`, `git diff --check` pass nếu có source changes; riêng document-only thay thế bằng link/lint docs khi hợp lý.
- **AC-G11-03-04:** Reviewer có đủ input versions, test logs đã redact, artifact paths và kết luận rõ PASS/FAIL/NEEDS_EVIDENCE.

## Acceptance test design
- Happy path: dùng input hợp lệ ở môi trường được phép, đo output theo AC-01.
- Failure path: Malicious dependency or joblib artifact từ bên ngoài: response?.
- Regression: chạy lại các test liên quan đến các ticket đã PASS; tránh sửa code/metric/split mà không cập nhật version.

## Evidence required
- Implementation plan 5–10 dòng + PR diff/commit.
- Test command, exit code và output tóm tắt (đã redact).
- Artifacts có hash/run ID khi liên quan dataset/model.
- Giải thích điều chưa được kiểm chứng và giới hạn của kết quả.

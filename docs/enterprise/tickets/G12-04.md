## Work breakdown (tự giải, không cung cấp solution)
Synthetic drift→approved dataset change→DVC/Prefect→run tracking→candidate→QA→registry→staging; independent auditor assess. Thiết kế trước khi code; nêu ít nhất 1 phương án thay thế và rủi ro. Thực hiện theo *small diff*, cập nhật tài liệu và tests tương ứng.

## Deliverables (paths do implementer chọn rồi khai trong PR)
End-to-end replay, architecture final, audit pack. Nộp `docs/enterprise/templates/SUBMISSION.md` với changed paths, chạy test có command/exit, commit SHA và risk statement. Không đẩy data/weights không được phép lên repo.

## Acceptance criteria (verifiable, no fake evidence)
- **AC-G12-04-01:** All 42 tickets traceable; denied candidate remains blocked; accepted champion has rollback.
- **AC-G12-04-02:** Có ít nhất một negative/edge case được kiểm thử độc lập: **Synthetic corrupted labels should trigger stop before training**.
- **AC-G12-04-03:** `python -m pytest -q`, `python -m ruff check src tests`, `git diff --check` pass nếu có source changes; riêng document-only thay thế bằng link/lint docs khi hợp lý.
- **AC-G12-04-04:** Reviewer có đủ input versions, test logs đã redact, artifact paths và kết luận rõ PASS/FAIL/NEEDS_EVIDENCE.

## Acceptance test design
- Happy path: dùng input hợp lệ ở môi trường được phép, đo output theo AC-01.
- Failure path: Synthetic corrupted labels should trigger stop before training.
- Regression: chạy lại các test liên quan đến các ticket đã PASS; tránh sửa code/metric/split mà không cập nhật version.

## Evidence required
- Implementation plan 5–10 dòng + PR diff/commit.
- Test command, exit code và output tóm tắt (đã redact).
- Artifacts có hash/run ID khi liên quan dataset/model.
- Giải thích điều chưa được kiểm chứng và giới hạn của kết quả.

# G4-03 — Reproduce baseline, predict & evidence report

**Epic/Gate:** G4
**Owner (function):** MLE+QA
**Depends on:** G4-02
**Priority:** P1 (learning sequence)
**Status at creation:** BACKLOG (chưa thực hiện/chưa nghiệm thu)

## User story / Why
Người khác tái lập được baseline và tạo submission hợp lệ.

## Existing starter implementation
Starter project đã có `scripts/05_predict_submission.py`; review conformity theo `sample_submission.csv` trước khi upload thật.

## Input & prerequisite
Các dependency phải PASS, phải có quyền data/server tương ứng, đã đọc `01_PROJECT_CHARTER_SRS.md` và `10_SECURITY_DATA_POLICY.md`. Nếu phần prerequisite thiếu, chuyển trạng thái `BLOCKED` và ghi rõ owner.

## Work breakdown (tự giải, không cung cấp solution)
Record hashes/environment; predict synthetic and sample_submission; write comparison B0/B1; failure audit. Thiết kế trước khi code; nêu ít nhất 1 phương án thay thế và rủi ro. Thực hiện theo *small diff*, cập nhật tài liệu và tests tương ứng.

## Deliverables (paths do implementer chọn rồi khai trong PR)
Baseline model card v0 + run manifest + submission schema check. Nộp `docs/enterprise/templates/SUBMISSION.md` với changed paths, chạy test có command/exit, commit SHA và risk statement. Không đẩy data/weights không được phép lên repo.

## Acceptance criteria (verifiable, no fake evidence)
- **AC-G4-03-01:** Independent replay with stable split + output schema; no actual test targets used.
- **AC-G4-03-02:** Có ít nhất một negative/edge case được kiểm thử độc lập: **Model file đã tồn tại, script overwrite silent: reject**.
- **AC-G4-03-03:** `python -m pytest -q`, `python -m ruff check src tests`, `git diff --check` pass nếu có source changes; riêng document-only thay thế bằng link/lint docs khi hợp lý.
- **AC-G4-03-04:** Reviewer có đủ input versions, test logs đã redact, artifact paths và kết luận rõ PASS/FAIL/NEEDS_EVIDENCE.

## Acceptance test design
- Happy path: dùng input hợp lệ ở môi trường được phép, đo output theo AC-01.
- Failure path: Model file đã tồn tại, script overwrite silent: reject.
- Regression: chạy lại các test liên quan đến các ticket đã PASS; tránh sửa code/metric/split mà không cập nhật version.

## Evidence required
- Implementation plan 5–10 dòng + PR diff/commit.
- Test command, exit code và output tóm tắt (đã redact).
- Artifacts có hash/run ID khi liên quan dataset/model.
- Giải thích điều chưa được kiểm chứng và giới hạn của kết quả.

## Learning checkpoint — tự trả lời trước review
**Model joblib/ pickle có rủi ro gì khi load từ nguồn lạ?**

## Merge decision
`RECOMMEND_APPROVE` chỉ khi tất cả AC đạt, không có P0/P1 và reviewer độc lập ký tên (agent review không thay GitHub approval). Nếu thiếu bằng chứng: `NEEDS_EVIDENCE`; nếu AC sai: `CHANGES_REQUESTED`; P0/P1: `BLOCKED`.

# G1-03 — Git repository and safe .gitignore

**Epic/Gate:** G1
**Owner (function):** Platform
**Depends on:** G1-01
**Priority:** P1 (learning sequence)
**Status at creation:** BACKLOG (chưa thực hiện/chưa nghiệm thu)

## User story / Why
Có thể version source mà không leak dữ liệu.

## Input & prerequisite
Các dependency phải PASS, phải có quyền data/server tương ứng, đã đọc `01_PROJECT_CHARTER_SRS.md` và `10_SECURITY_DATA_POLICY.md`. Nếu phần prerequisite thiếu, chuyển trạng thái `BLOCKED` và ghi rõ owner.

## Work breakdown (tự giải, không cung cấp solution)
Init Git tương thích 2.25; kiểm tra tracked files; ban secrets/data/model/cache; định nghĩa naming. Thiết kế trước khi code; nêu ít nhất 1 phương án thay thế và rủi ro. Thực hiện theo *small diff*, cập nhật tài liệu và tests tương ứng.

## Deliverables (paths do implementer chọn rồi khai trong PR)
Git main initial commit + ignore review. Nộp `docs/enterprise/templates/SUBMISSION.md` với changed paths, chạy test có command/exit, commit SHA và risk statement. Không đẩy data/weights không được phép lên repo.

## Acceptance criteria (verifiable, no fake evidence)
- **AC-G1-03-01:** git status sạch sau commit; không tracked raw data/keys; không force-push.
- **AC-G1-03-02:** Có ít nhất một negative/edge case được kiểm thử độc lập: **Thêm file credentials giả vào git add: pre-commit kiểm tra thế nào?**.
- **AC-G1-03-03:** `python -m pytest -q`, `python -m ruff check src tests`, `git diff --check` pass nếu có source changes; riêng document-only thay thế bằng link/lint docs khi hợp lý.
- **AC-G1-03-04:** Reviewer có đủ input versions, test logs đã redact, artifact paths và kết luận rõ PASS/FAIL/NEEDS_EVIDENCE.

## Acceptance test design
- Happy path: dùng input hợp lệ ở môi trường được phép, đo output theo AC-01.
- Failure path: Thêm file credentials giả vào git add: pre-commit kiểm tra thế nào?.
- Regression: chạy lại các test liên quan đến các ticket đã PASS; tránh sửa code/metric/split mà không cập nhật version.

## Evidence required
- Implementation plan 5–10 dòng + PR diff/commit.
- Test command, exit code và output tóm tắt (đã redact).
- Artifacts có hash/run ID khi liên quan dataset/model.
- Giải thích điều chưa được kiểm chứng và giới hạn của kết quả.

## Learning checkpoint — tự trả lời trước review
**Khác biệt source vs data versioning?**

## Merge decision
`RECOMMEND_APPROVE` chỉ khi tất cả AC đạt, không có P0/P1 và reviewer độc lập ký tên (agent review không thay GitHub approval). Nếu thiếu bằng chứng: `NEEDS_EVIDENCE`; nếu AC sai: `CHANGES_REQUESTED`; P0/P1: `BLOCKED`.

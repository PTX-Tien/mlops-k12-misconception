**Epic/Gate:** G3
**Owner (function):** QA+MLE
**Depends on:** G3-01
**Priority:** P1 (learning sequence)
**Status at creation:** BACKLOG (chưa thực hiện/chưa nghiệm thu)

## User story / Why
Metric chính xác, xử lý edge cases.

## Existing starter implementation
Starter project đã có `src/k12mlops/metrics.py` và unit tests. Task yêu cầu **audit tính đúng, bổ sung edge tests và đối chiếu metric chính thức**, không reimplement mù quáng.

## Input & prerequisite
Các dependency phải PASS, phải có quyền data/server tương ứng, đã đọc `01_PROJECT_CHARTER_SRS.md` và `10_SECURITY_DATA_POLICY.md`. Nếu phần prerequisite thiếu, chuyển trạng thái `BLOCKED` và ghi rõ owner.

## Work breakdown (tự giải, không cung cấp solution)
Xây fixture rank 1/2/3/out; assert uniqueness; validate NONE and unseen class behavior. Thiết kế trước khi code; nêu ít nhất 1 phương án thay thế và rủi ro. Thực hiện theo *small diff*, cập nhật tài liệu và tests tương ứng.

## Deliverables (paths do implementer chọn rồi khai trong PR)
Metric specification + unit tests + manual worked example. Nộp `docs/enterprise/templates/SUBMISSION.md` với changed paths, chạy test có command/exit, commit SHA và risk statement. Không đẩy data/weights không được phép lên repo.

## Acceptance criteria (verifiable, no fake evidence)
- **AC-G3-02-01:** Đối chiếu official metric; tính tay khớp test; reject duplicate/invalid rank.
- **AC-G3-02-02:** Có ít nhất một negative/edge case được kiểm thử độc lập: **Danh sách dự đoán có mã lặp/thiếu: trả lỗi hay điều chỉnh?**.
- **AC-G3-02-03:** `python -m pytest -q`, `python -m ruff check src tests`, `git diff --check` pass nếu có source changes; riêng document-only thay thế bằng link/lint docs khi hợp lý.
- **AC-G3-02-04:** Reviewer có đủ input versions, test logs đã redact, artifact paths và kết luận rõ PASS/FAIL/NEEDS_EVIDENCE.

## Acceptance test design
- Happy path: dùng input hợp lệ ở môi trường được phép, đo output theo AC-01.
- Failure path: Danh sách dự đoán có mã lặp/thiếu: trả lỗi hay điều chỉnh?.
- Regression: chạy lại các test liên quan đến các ticket đã PASS; tránh sửa code/metric/split mà không cập nhật version.

## Evidence required
- Implementation plan 5–10 dòng + PR diff/commit.
- Test command, exit code và output tóm tắt (đã redact).
- Artifacts có hash/run ID khi liên quan dataset/model.
- Giải thích điều chưa được kiểm chứng và giới hạn của kết quả.

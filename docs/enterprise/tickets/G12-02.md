# G12-02 — Drift monitoring & feedback contract

**Epic/Gate:** G12
**Owner (function):** MLE+DE
**Depends on:** G12-01
**Priority:** P1 (learning sequence)
**Status at creation:** BACKLOG (chưa thực hiện/chưa nghiệm thu)

## User story / Why
Phân biệt data shift, model degradation, delayed labels.

## Input & prerequisite
Các dependency phải PASS, phải có quyền data/server tương ứng, đã đọc `01_PROJECT_CHARTER_SRS.md` và `10_SECURITY_DATA_POLICY.md`. Nếu phần prerequisite thiếu, chuyển trạng thái `BLOCKED` và ghi rõ owner.

## Work breakdown (tự giải, không cung cấp solution)
Monitor safe aggregates/OOD; define feedback schema/privacy; simulate covariate shift. Thiết kế trước khi code; nêu ít nhất 1 phương án thay thế và rủi ro. Thực hiện theo *small diff*, cập nhật tài liệu và tests tương ứng.

## Deliverables (paths do implementer chọn rồi khai trong PR)
Drift report + feedback contract + tests. Nộp `docs/enterprise/templates/SUBMISSION.md` với changed paths, chạy test có command/exit, commit SHA và risk statement. Không đẩy data/weights không được phép lên repo.

## Acceptance criteria (verifiable, no fake evidence)
- **AC-G12-02-01:** Trigger needs sample threshold; do not claim accuracy drop without ground truth.
- **AC-G12-02-02:** Có ít nhất một negative/edge case được kiểm thử độc lập: **Data drift but stable quality: action?**.
- **AC-G12-02-03:** `python -m pytest -q`, `python -m ruff check src tests`, `git diff --check` pass nếu có source changes; riêng document-only thay thế bằng link/lint docs khi hợp lý.
- **AC-G12-02-04:** Reviewer có đủ input versions, test logs đã redact, artifact paths và kết luận rõ PASS/FAIL/NEEDS_EVIDENCE.

## Acceptance test design
- Happy path: dùng input hợp lệ ở môi trường được phép, đo output theo AC-01.
- Failure path: Data drift but stable quality: action?.
- Regression: chạy lại các test liên quan đến các ticket đã PASS; tránh sửa code/metric/split mà không cập nhật version.

## Evidence required
- Implementation plan 5–10 dòng + PR diff/commit.
- Test command, exit code và output tóm tắt (đã redact).
- Artifacts có hash/run ID khi liên quan dataset/model.
- Giải thích điều chưa được kiểm chứng và giới hạn của kết quả.

## Learning checkpoint — tự trả lời trước review
**PSI/distance khác concept drift?**

## Merge decision
`RECOMMEND_APPROVE` chỉ khi tất cả AC đạt, không có P0/P1 và reviewer độc lập ký tên (agent review không thay GitHub approval). Nếu thiếu bằng chứng: `NEEDS_EVIDENCE`; nếu AC sai: `CHANGES_REQUESTED`; P0/P1: `BLOCKED`.

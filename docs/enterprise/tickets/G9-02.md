# G9-02 — Model acceptance & human approval policy

**Epic/Gate:** G9
**Owner (function):** TL+QA
**Depends on:** G9-01; G8-03
**Priority:** P1 (learning sequence)
**Status at creation:** BACKLOG (chưa thực hiện/chưa nghiệm thu)

## User story / Why
Không tự động promote khi model regress hoặc thiếu evidence.

## Input & prerequisite
Các dependency phải PASS, phải có quyền data/server tương ứng, đã đọc `01_PROJECT_CHARTER_SRS.md` và `10_SECURITY_DATA_POLICY.md`. Nếu phần prerequisite thiếu, chuyển trạng thái `BLOCKED` và ghi rõ owner.

## Work breakdown (tự giải, không cung cấp solution)
Implement automated precheck, human decision template; exercise reject candidate. Thiết kế trước khi code; nêu ít nhất 1 phương án thay thế và rủi ro. Thực hiện theo *small diff*, cập nhật tài liệu và tests tương ứng.

## Deliverables (paths do implementer chọn rồi khai trong PR)
Acceptance gate + mock reject/approve record. Nộp `docs/enterprise/templates/SUBMISSION.md` với changed paths, chạy test có command/exit, commit SHA và risk statement. Không đẩy data/weights không được phép lên repo.

## Acceptance criteria (verifiable, no fake evidence)
- **AC-G9-02-01:** Hard gates block regardless of score; explicit accountable sign-off.
- **AC-G9-02-02:** Có ít nhất một negative/edge case được kiểm thử độc lập: **Candidate positive MAP but NONE FP unacceptable => reject**.
- **AC-G9-02-03:** `python -m pytest -q`, `python -m ruff check src tests`, `git diff --check` pass nếu có source changes; riêng document-only thay thế bằng link/lint docs khi hợp lý.
- **AC-G9-02-04:** Reviewer có đủ input versions, test logs đã redact, artifact paths và kết luận rõ PASS/FAIL/NEEDS_EVIDENCE.

## Acceptance test design
- Happy path: dùng input hợp lệ ở môi trường được phép, đo output theo AC-01.
- Failure path: Candidate positive MAP but NONE FP unacceptable => reject.
- Regression: chạy lại các test liên quan đến các ticket đã PASS; tránh sửa code/metric/split mà không cập nhật version.

## Evidence required
- Implementation plan 5–10 dòng + PR diff/commit.
- Test command, exit code và output tóm tắt (đã redact).
- Artifacts có hash/run ID khi liên quan dataset/model.
- Giải thích điều chưa được kiểm chứng và giới hạn của kết quả.

## Learning checkpoint — tự trả lời trước review
**PR approval khác model promotion?**

## Merge decision
`RECOMMEND_APPROVE` chỉ khi tất cả AC đạt, không có P0/P1 và reviewer độc lập ký tên (agent review không thay GitHub approval). Nếu thiếu bằng chứng: `NEEDS_EVIDENCE`; nếu AC sai: `CHANGES_REQUESTED`; P0/P1: `BLOCKED`.

# G10-03 — Latency, parity and reliability testing

**Epic/Gate:** G10
**Owner (function):** QA+SRE
**Depends on:** G10-02
**Priority:** P1 (learning sequence)
**Status at creation:** BACKLOG (chưa thực hiện/chưa nghiệm thu)

## User story / Why
Chứng minh hệ thống phục vụ được và có giới hạn.

## Input & prerequisite
Các dependency phải PASS, phải có quyền data/server tương ứng, đã đọc `01_PROJECT_CHARTER_SRS.md` và `10_SECURITY_DATA_POLICY.md`. Nếu phần prerequisite thiếu, chuyển trạng thái `BLOCKED` và ghi rõ owner.

## Work breakdown (tự giải, không cung cấp solution)
Batch/API prediction parity; profile p50/p95/peak memory; errors under malformed inputs; define baseline. Thiết kế trước khi code; nêu ít nhất 1 phương án thay thế và rủi ro. Thực hiện theo *small diff*, cập nhật tài liệu và tests tương ứng.

## Deliverables (paths do implementer chọn rồi khai trong PR)
Performance report + service runbook. Nộp `docs/enterprise/templates/SUBMISSION.md` với changed paths, chạy test có command/exit, commit SHA và risk statement. Không đẩy data/weights không được phép lên repo.

## Acceptance criteria (verifiable, no fake evidence)
- **AC-G10-03-01:** Measured not guessed; parity successful; failure paths tested.
- **AC-G10-03-02:** Có ít nhất một negative/edge case được kiểm thử độc lập: **Load malformed model/error during request: graceful health**.
- **AC-G10-03-03:** `python -m pytest -q`, `python -m ruff check src tests`, `git diff --check` pass nếu có source changes; riêng document-only thay thế bằng link/lint docs khi hợp lý.
- **AC-G10-03-04:** Reviewer có đủ input versions, test logs đã redact, artifact paths và kết luận rõ PASS/FAIL/NEEDS_EVIDENCE.

## Acceptance test design
- Happy path: dùng input hợp lệ ở môi trường được phép, đo output theo AC-01.
- Failure path: Load malformed model/error during request: graceful health.
- Regression: chạy lại các test liên quan đến các ticket đã PASS; tránh sửa code/metric/split mà không cập nhật version.

## Evidence required
- Implementation plan 5–10 dòng + PR diff/commit.
- Test command, exit code và output tóm tắt (đã redact).
- Artifacts có hash/run ID khi liên quan dataset/model.
- Giải thích điều chưa được kiểm chứng và giới hạn của kết quả.

## Learning checkpoint — tự trả lời trước review
**SLO vs SLA vs observed baseline?**

## Merge decision
`RECOMMEND_APPROVE` chỉ khi tất cả AC đạt, không có P0/P1 và reviewer độc lập ký tên (agent review không thay GitHub approval). Nếu thiếu bằng chứng: `NEEDS_EVIDENCE`; nếu AC sai: `CHANGES_REQUESTED`; P0/P1: `BLOCKED`.
